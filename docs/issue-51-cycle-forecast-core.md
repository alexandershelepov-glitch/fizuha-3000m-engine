# Issue #51 — рабочее ядро полного прогноза цикла

Production-модуль `src/forecast.ts` (ветка `feature/issue-51-cycle-forecast-core`, база `1e299b83`).
API создан на основе завершённого эксперимента `experiment/issue-51-forecast-spike` (модели А/Б);
экспериментальный код не переносился механически, аудиторские сценарии не используются.

## API

```ts
forecastCycle(state: EngineState, options: {mode: ForecastMode; asOf?: string}): ForecastResult
```

- `RESERVATION` — консервативное бронирование (модель А): после загрузки состояния не выполняется
  ни одного перехода; будущие цикл-недели генерируются `generateQueue` + `guardWeeklyLoad`
  (публичные функции ядра) со всей цепочкой броней. Будущие назначения резервируют нагрузку и
  восстановление, но не начисляют успехи и не становятся пропусками.
- `CONDITIONAL` — условный сценарий «при успешном выполнении» (модель Б) в изолированной копии:
  синтетический успешный отчёт по каждому назначению; контрольные 3000 м и итог — только прежний
  известный результат (без улучшения времени). Не допуск к нагрузке.

`ForecastResult` возвращает: действующую очередь дословно (`COMMITTED`), прогнозные задания
(`CONSERVATIVE`/`CONDITIONAL`), неразрешённые слоты (`UNRESOLVED`) и неразрешённые контрольные
точки (`blockingReasons`, например `CHECKPOINT_DUE`); решение движка на дату каждого назначения;
бронь резерва и утверждённый бюджет; события (контрольные окна, устаревание измерения, TAPER);
`seedDigest`/`seedUnchanged` — контракт побайтовой неизменности входного состояния;
`windowViolations` — сквозная проверка всех скользящих 7-дневных окон (включая стыки недель).

`asOf` по умолчанию равен `state.asOf`; допускается более поздняя дата (просроченные слоты
закроются реальными правилами движка). `CLOCK_BACKWARDS`/`EVENT_DATE_PASSED` — прежние коды ошибок.
Старые сохранённые состояния нормализуются через `deserialize`, как при загрузке приложения.

## Границы

- Модуль не изменяет спортивную методику, `EngineState`, UI и хранилище; он только читает состояние
  и вызывает существующие операции/чистые функции ядра.
- Прогнозные результаты никогда не записываются в состояние пользователя; расчёт детерминирован
  и не зависит от `localStorage`.
- Без измеренного результата 3000 м темп не выдумывается (новичок остаётся на RUN_WALK без темпа);
  способность пробежать 3 км не подтверждается.
