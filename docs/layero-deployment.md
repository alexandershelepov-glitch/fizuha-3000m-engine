# Публикация «ФИЗУХА — 3000 м» на Layero

Репозиторий остаётся приватным; публичным становится **только собранный сайт**.
У Layero Free есть HTTPS-поддомен и автоматическая сборка при push.
Собственные домены и отказ от плашки Layero требуют платного тарифа.

## Подключение (один раз через браузер владельца)

1. Откройте https://app.layero.ru/ и войдите **через GitHub**.
   Для импорта GitHub-репозитория нужен связанный GitHub-аккаунт.
2. «Создать проект» → «Импортировать из GitHub».
3. Выберите alexandershelepov-glitch/fizuha-3000m-engine.
   При выдаче разрешений желательно выбрать «Only select repositories»
   и разрешить доступ только к этому репозиторию.
4. Production branch = main; каталог приложения = корень репозитория
   (не web/: движок расположен в соседнем каталоге src/).
5. Конфигурация `layero.json` в корне уже задаёт:
   - buildCommand = npm run build:layero
   - outputDirectory = web/dist
   - framework = Vite (Layero обнаруживает из vite.config.ts)
   - Node.js берётся из package.json engines (>=22.18.0)
6. Нажмите «Deploy» и дождитесь статуса READY.
   Скопируйте фактический адрес вида https://<имя>.layero.app.
7. Проверьте главную, анкету, обновление страницы и сохранение
   тренировочного плана. Пришлите адрес для независимой проверки.

**Важно:** репозиторий НЕ требуется делать публичным. При ошибке импорта
проверьте GitHub App / OAuth доступ именно к этому приватному репозиторию.

## Почему Layero отличается от ранее настроенного GitHub Pages

- Layero публикует сайт в корне HTTPS-домена, не в подпапке GitHub Pages.
- В `vite.config.ts` production `base` по умолчанию равен `/`.
- `build:layero` создаёт `web/dist/index.html` и набор JS/CSS/иконок.
- Нельзя публиковать файл `404.html` из сборки Pages: у Layero он
  отключит нужный SPA-fallback со статусом 200 для прямых ссылок.
- Service worker сохраняет основной интерфейс для офлайна и получает
  новый идентификатор из хеша реальных файлов сборки при обновлении.
- GitHub Pages workflow остаётся доступным вручную, но на push
  больше не запускается — используется автодеплой Layero по GitHub webhook.

## Локальные проверки

```
npm ci
npm run build:layero
npm run test:e2e
```

Прямые ссылки на страницы проверяются Playwright в Chrome mobile viewport.
Реальную установку на iPhone/Android нужно проверить отдельно.

## Конфиденциальность пилота

В версии MVP данные сохраняются в localStorage устройства и не
синхронизируются между браузерами. Удаление данных браузера может уничтожить
журнал тренировок. Пока нет экспорта/резервных копий, используйте тестовые
данные и не обещайте сотрудникам безусловную сохранность информации.
