ЗАДАЧА: ядро адаптивного тренировочного движка «3000 м» v1.0

Работай как автономный инженер над этой задачей до проверенного результата.

Сначала изучи текущее состояние выбранной рабочей директории и составь для себя краткий план реализации. После этого выполняй задачу самостоятельно.

Для безопасных локальных действий — создание и изменение файлов проекта, установка разумно необходимых dev-зависимостей, запуск тестов, линтера и сборки — отдельное подтверждение на каждом шаге не требуется.

Если обнаружишь реальное противоречие спортивной спецификации, не придумывай молча новое спортивное правило. Зафиксируй проблему и выбери только минимальное техническое поведение, необходимое для продолжения работы.


==================================================
ЦЕЛЬ
==================================================

Создать изолированное программное ядро адаптивной подготовки пользователя к бегу на 3000 м.

Сейчас НЕ создаётся полноценное приложение и НЕ создаётся пользовательский интерфейс.

Ядро должно программно выполнять полный цикл:

данные пользователя
→ оценка текущего состояния
→ оценка цели
→ выбор тренировочной фазы
→ выбор допустимой нагрузки
→ создание очереди тренировок
→ получение результата тренировки
→ классификация реакции
→ адаптация последующих тренировок
→ контрольная точка
→ обновление состояния и оставшегося плана.

Это должен быть общий детерминированный движок.

Запрещено реализовывать 12 тестовых персонажей как 12 отдельных заранее написанных программ тренировок.


==================================================
ИСХОДНЫЕ ДАННЫЕ
==================================================

Проект является первым рабочим прототипом модуля подготовки к дистанции 3000 м.

Модули 100 м, подтягиваний и объединения разных дисциплин сейчас не учитывать.

Будущий продукт — web/PWA.

Если рабочая директория не содержит существующего проекта, выбери минимальную архитектуру, позволяющую использовать созданное ядро в будущем web/PWA без переписывания спортивной логики.

При создании нового проекта предпочтителен TypeScript, если нет веской технической причины выбрать другой вариант.

Не создавать backend, базу данных, авторизацию и runtime-зависимость от LLM — они для проверки движка сейчас не нужны.

==================================================
4. SAFETY GATE
==================================================

Safety имеет абсолютный приоритет над спортивной целью.

STOP должен блокировать обычную интенсивную тренировочную прогрессию.

К STOP относятся как минимум:

— нарастающая боль;
— изменение техники движения из-за боли;
— боль при обычной ходьбе или в покое;
— выраженный отёк;
— острое заболевание;
— другие явно заданные safety stop conditions.

Состояние HOLD временно блокирует обычную спортивную прогрессию, если ситуация требует дополнительной оценки, но STOP ещё не установлен.

При Safety != OK нельзя продолжать нормальную спортивную прогрессию только потому, что приближается дата старта.


==================================================
5. CURRENT PERFORMANCE
==================================================

Если имеется валидный результат 3000 м:

current_speed = 3000 / current_time_seconds

current_pace_seconds_per_km = current_time_seconds / 3

Current Performance разрешается точно изменить только после:

— нового валидного теста 3000 м;
— официального результата 3000 м;
— либо будущей отдельно утверждённой модели прогнозирования.

Обычная тренировка не имеет права сама объявлять новое прогнозное время 3000 м.


==================================================
6. PERFORMANCE CONFIDENCE
==================================================

LOW:

— результата нет;
— либо результат старше 42 дней;
— либо после теста был перерыв >14 дней;
— либо после него была болезнь/травма;
— либо свежие данные явно противоречат старому результату.

MEDIUM:

если LOW отсутствует и есть хотя бы одно:

— результату 22–42 дня;
— здоровый перерыв 4–14 дней;
— умеренное расхождение последних тренировок с тестом.

HIGH:

— тест ≤21 дня;
— значимого перерыва не было;
— болезни/травмы после теста не было;
— свежие тренировки примерно подтверждают уровень.

Если результата 3000 м нет:

UNKNOWN.


==================================================
7. TRAINING CAPACITY
==================================================

Категорию определять консервативно.

T3 требует одновременно:

— регулярный бег ≥12 недель;
— ≥4 тренировок/неделю;
— ≥25 км/неделю;
— обычная длинная пробежка ≥8 км.

T2, если T3 не выполнен:

— регулярный бег ≥8 недель;
— ≥3 тренировок;
— ≥15 км/неделю;
— длинная пробежка ≥6 км.

T1, если T2 не выполнен:

— регулярный бег ≥4 недель;
— ≥2 тренировок;
— ≥8 км/неделю;
— способность непрерывно пробежать ≥3 км.

T0:

остальные случаи.

Использовать фактическую привычную нагрузку, а не число тренировок, которое пользователь только собирается выполнять.


==================================================
8. QUALITY EXPERIENCE
==================================================

Q2:

качественная работа выполнялась минимум в 6 разных неделях из последних 8 и в основном переносилась нормально.

Q1:

примерно 3–7 качественных тренировок за последние 8 недель.

Q0:

менее 3 либо отсутствие такого опыта.

При этом отдельно сохранять наличие опыта:

threshold
vo2
specific_3k

Общий Q не должен подменять эти признаки.


==================================================
9. GOAL GAP
==================================================

Использовать:

goal_gap = current_time / target_time - 1

Например:

15:20 → 14:56 ≈ 2,7%.

18:20 → 13:30 ≈ 35,8%.

Если Current Performance неизвестна:

goal_gap = null.


==================================================
10. GOAL FEASIBILITY
==================================================

Базовое правило:

Goal Gap >15%:
LONG_TERM.

10–15%:
если срок ≥12 недель и T2+ → AMBITIOUS;
иначе → LOW_PROBABILITY.

6–10%:
≥10 недель и T2+ → PLAUSIBLE;
6–9 недель → AMBITIOUS;
<6 недель → LOW_PROBABILITY.

3–6%:
≥6 недель → PLAUSIBLE;
4–5 недель → AMBITIOUS;
<4 недель → LOW_PROBABILITY.

≤3%:
≥3 недель → PLAUSIBLE;
иначе → AMBITIOUS.


При Goal Gap >3% применить модификаторы:

T0/T1 → понизить на одну ступень.

Q0 → понизить ещё на одну ступень.

Только 2 доступные тренировки → понизить ещё на одну ступень.

Шкала:

PLAUSIBLE
→ AMBITIOUS
→ LOW_PROBABILITY.

LONG_TERM через эту шкалу не понижается.

Goal Feasibility не является обещанием результата.


==================================================
11. ВЫБОР PHASE
==================================================

Приоритеты:

Safety != OK
→ HOLD_DIAGNOSTIC.

Нет Current Performance либо пользователь не способен пробежать 3 км
→ FOUNDATION.

T0
→ FOUNDATION.

Значимый здоровый перерыв
→ при необходимости RE_ENTRY.

Performance Confidence LOW
→ HOLD_DIAGNOSTIC либо FOUNDATION в зависимости от текущей способности тренироваться.

До старта остался индивидуальный taper-период
→ TAPER.

SPECIFIC разрешается только при одновременном выполнении:

— T2/T3;
— Q1/Q2;
— Goal Gap ≤8%;
— Confidence HIGH/MEDIUM;
— минимум две успешные качественные тренировки текущего цикла;
— Safety OK.

Остальные подготовленные пользователи:
DEVELOPMENT.


==================================================
12. КОЛИЧЕСТВО QUALITY SESSIONS
==================================================

2 доступные тренировки:
максимум 1 quality.

3 доступные:
обычно максимум 1 quality.

4+:
две quality разрешены только при:

— T2/T3;
— Q1/Q2;
— Safety OK;
— отсутствии RED;
— отсутствии двух связанных YELLOW.

Абсолютный максимум:
2 полноценные quality sessions в неделю.

STRIDES отдельной полноценной quality session не считаются.


==================================================
13. TARGET PACE GATE
==================================================

CLOSED обязателен, если:

— Goal Gap >8%;
— Confidence LOW/UNKNOWN;
— FOUNDATION;
— RE_ENTRY;
— Safety != OK;
— качественная работа ещё не подтверждена.

При CLOSED Target Speed не используется как основная специфическая скорость.


PARTIAL разрешается при:

— Confidence HIGH/MEDIUM;
— Goal Gap ≤8%;
— Safety OK.

Дополнительно:

Q0 → минимум две успешные вводные quality sessions.

Q1/Q2 при Gap ≤5% → минимум одна успешная подтверждающая quality session.

Effective Speed:

CurrentSpeed + 0.5 × (TargetSpeed - CurrentSpeed)


OPEN требует одновременно:

— Goal Gap ≤5%;
— Confidence HIGH/MEDIUM;
— минимум две успешные SPECIFIC_3K при PARTIAL;
— отсутствие связанных YELLOW;
— Safety OK.

При OPEN:

EffectiveSpeed = TargetSpeed.


==================================================
14. ВЫБОР QUALITY WORKOUT
==================================================

FOUNDATION:

Easy
Long Easy
Strides
Intro Quality / короткий fartlek.

Полноценные VO2 и SPECIFIC_3K запрещены.


DEVELOPMENT + Q0:

сначала INTRO_QUALITY.

После адаптации может появляться THRESHOLD.

Полноценная VO2-сессия не должна быть первым качественным занятием.


DEVELOPMENT + Q1/Q2:

при одной quality в неделю:

THRESHOLD и VO2 чередуются.

При двух:

одна THRESHOLD,
одна VO2.


SPECIFIC:

основная quality:
SPECIFIC_3K.

Дополнительная quality, если разрешена:
чередование THRESHOLD / VO2.


RE_ENTRY:

до обязательных Easy-сессий quality отсутствует.


TAPER:

новая большая развивающая нагрузка запрещена.


==================================================
15. РАБОЧАЯ ИНТЕНСИВНОСТЬ
==================================================

EASY:

— RPE 2–3;
— разговор полными фразами;
— контролируемое дыхание.

Не задавать Easy исключительно процентом от результата 3000 м.


THRESHOLD:

стартовый ориентир:
90–94% Current 3K Speed.

RPE:
6–7.


VO2:

97–103% Current 3K Speed.

RPE:
8–9.


SPECIFIC_3K:

центр нагрузки = Effective Speed.

Рабочий диапазон первой версии:
примерно ±1,5% вокруг Effective Speed.

Q0:

INTRO_QUALITY:
4–8 минут суммарной быстрой работы.


Q1:

Threshold:
12–18 минут.

VO2:
8–12 минут.

Specific:
примерно 1,8–2,4 км.


Q2:

Threshold:

==================================================
17. РЕЗУЛЬТАТ ТРЕНИРОВКИ
==================================================

Сохранять как минимум:

— долю выполненного задания;
— session RPE;
— боль;
— динамику боли;
— изменение движения;
— длительность;
— дистанцию;
— фактические результаты повторов;
— отдых между повторами;
— причину YELLOW;
— контекст условий.

Допускается:

session_load = session_rpe × duration_minutes

Но не вводить универсальный «опасный порог» session load.


==================================================
18. GREEN / GREEN+ / YELLOW / RED
==================================================

RED проверяется первым.


GREEN_PLUS:

— выполнено 100%;
— минимум 80% повторов в диапазоне;
— нет выраженного падения скорости;
— RPE минимум на 1 ниже планового;
— боль ≤1 и не растёт.


GREEN:

— выполнено ≥95%;
— минимум 80% повторов в диапазоне;
— падение скорости ≤5%;
— RPE примерно ±1 от цели;
— боль ≤1.


YELLOW:

если RED отсутствует, но выполнено хотя бы одно:

— выполнено <95%;
— значительная часть повторов вне диапазона;
— падение скорости >5%;
— RPE ≥ target +2;
— боль 2–3;
— неожиданно сильное утомление.

Обязательно определить Yellow Reason.


RED:

— нарастающая боль;
— изменение движения;
— боль при ходьбе/в покое;
— выраженный отёк;
— острое заболевание;
— иной Safety Stop.


==================================================
19. АДАПТАЦИЯ
==================================================

Один GREEN:
сохранить уровень.

Два успешных подтверждения:
разрешить один небольшой шаг прогрессии.

Один GREEN_PLUS:
не пересчитывать Current Performance.

Два независимых GREEN_PLUS:
checkpoint_required = true.

Один YELLOW:
прогрессия блокируется;
следующее действие зависит от причины.

Два YELLOW объединять только при сопоставимых причинах.

Два связанных YELLOW:

— остановить прогрессию;
— вернуться к последней подтверждённой дозе;
— временно уменьшить quality;
— HOLD_DIAGNOSTIC;
— Current Performance автоматически не снижать.

RED:
обычная спортивная прогрессия прекращается.


==================================================
20. ПРОГРЕССИЯ
==================================================

За один переход существенно изменять преимущественно один главный параметр.

Обычный максимальный шаг:

Q0:
+до 2 минут либо около 400 м quality volume.

Q1:
+до 3 минут либо 400–600 м.

Q2:
+до 4 минут либо около 600 м.

Длина отдельного повтора:
обычно +100–200 м.

Скорость:
примерно +2–5 сек/км.

Отдых:
не более −10% либо −15 секунд.

Не увеличивать одновременно заметно:

скорость,
объём,
длину повторов,
плотность.


==================================================
21. RE_ENTRY
==================================================

Для здорового немедицинского перерыва.

1–3 дня:
продолжить программу;
ничего не догонять.

4–7 дней:
первая Easy = 70–90% обычного объёма;
первая Quality = 80–90% последней подтверждённой дозы.

8–14 дней:
Phase = RE_ENTRY;
первые две тренировки Easy = 60–80%;
первая последующая Quality = 70–80%;
Target Pace Gate = CLOSED.

>14 дней:
Performance Confidence = LOW;
Quality блокируется;
после 2–3 успешных Easy нужна диагностическая оценка.

Перерывы из-за болезни или травмы не обрабатывать простой календарной формулой.


==================================================
22. ПРОПУСК ТРЕНИРОВКИ
==================================================

Не создавать training debt.

Пропущенная тренировка:

— переносится;
— либо удаляется.

Она никогда автоматически не увеличивает следующую нагрузку.

Не проводить две тяжёлые тренировки подряд только ради компенсации пропуска.


==================================================
23. КОНТРОЛЬНАЯ ТОЧКА
==================================================

checkpoint_required должен активироваться минимум при:

— примерно 3–4 неделях с предыдущей оценки;
— двух GREEN_PLUS;
— завершении значимого RE_ENTRY;
— устойчивом противоречии между Current Performance и свежими тренировками.

Точный Current Performance обновляется только после валидного контрольного результата.


==================================================
24. ПОЛЬЗОВАТЕЛЬ БЕЗ РЕЗУЛЬТАТА
==================================================

Если пользователь не способен непрерывно пробежать 3 км:

Phase = FOUNDATION.

Target Pace Gate = CLOSED.

Когда пользователь становится способен устойчиво пробегать 3 км, назначается исходная контрольная оценка.

После результата создаётся первый Performance Snapshot.


==================================================
25. TAPER
==================================================

T0/T1:
примерно 3–5 дней.

T2:
примерно 5–7 дней.

T3/Q2:
примерно 7–10 дней.

В TAPER:

— прогрессия запрещена;
— объём уменьшается;
— небольшой скоростной стимул может сохраняться;
— пропущенная интенсивная работа не догоняется.


==================================================
26. WORKOUT QUEUE
==================================================

Не привязывать внутреннюю модель обязательно к понедельнику, среде и пятнице.

Использовать очередь тренировок.

Каждая тренировка должна содержать данные, достаточные как минимум для:

— типа;
— цели;
— приоритета;
