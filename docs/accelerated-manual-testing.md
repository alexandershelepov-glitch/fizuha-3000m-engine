# «ФИЗУХА — 3000 м»: ускоренный ручной тест за 60–90 минут

## Безопасность и изоляция

Эта ветка `testing/virtual-clock` **НЕ должна объединяться с `main`**:
виртуальный календарь предназначен только для отдельного тестового сайта Layero.
Обычная рабочая ссылка на `main` не затрагивается.
Подмена даты в этом сайте предназначена только для тестирования.
Записанные «результаты» вымышлены и не должны интерпретироваться как
фактические пробежки или доказательство полезности/безопасности плана.

Ветка содержит свой `layero.json`:
- ветка: `testing/virtual-clock`
- сборка: `npm run build:testing`
- выход: `web/dist`

На Layero выберите новое имя проекта, например `fizuha-training-lab`,
чтобы тестовый и основной сайты находились на разных поддоменах.
**Никогда не меняйте у существующего Production-проекта ветку с main.**

## Как использовать календарь

Сверху каждого экрана появляется контрастная надпись «ТЕСТОВАЯ ВЕРСИЯ»,
виртуальная дата и кнопки «+1 день» и «+7 дней».

1. Заполните анкету тестовыми данными и посмотрите первую неделю.
2. На дне тренировки откройте карточку, изучите описание, внесите
   вымышленный результат только для испытания логики.
3. Переходите на следующий день. День отдыха можно просто пропустить.
4. Для проверки реакции на пропуски перейдите на 7 дней вперёд,
   не закрывая тренировку. Должно появиться «Предыдущая тренировка
   ещё не закрыта». Выберите «Внести результат» или «Не выполнено».
5. **Не придумывайте выполнения автоматически.** Приложение не присваивает
   GREEN, пока вы не ввели полный отчёт. Недельные лимиты, проверки
   нагрузки и медицинские ограничения остаются действующими.
6. За 8–12 недель дойдите до даты сдачи и введите итоговый результат.
7. Начните новый цикл для следующего профиля.

При переключении даты она сохраняется после перезагрузки страницы.
Для начала нового испытания с другой датой лучше использовать отдельный
тестовый профиль браузера или очистить данные **только тестового домена**.
Для повторного прохождения анкеты с той же виртуальной датой используйте
штатное действие нового цикла/сброса в приложении.

## Три обязательных профиля

- 3000 м за 18:00, привычный объём около 5–10 км/нед, цель 14:56,
  дата экзамена через 8 недель. Не должно быть обещаний гарантированной
  сдачи и резких скачков объёма.
- 3000 м за 15:30, привычный объём около 12–18 км/нед, цель 14:56,
  дата экзамена через 8 недель. Проверить адекватность темпа и пробежек.
- 3000 м за 14:30, привычный объём около 25–30 км/нед, цель 13:30,
  дата экзамена через 10 недель. Проверить интервалы, восстановление,
  отсутствие слишком частых сложных занятий.

В КАЖДОМ профиле: 2 успешные недели → одна частичная тренировка →
4 дня пропуска → усталость или боль (не утверждать улучшение самочувствия
без реальных данных) → изменение результата 3000 м → последние 7 дней →
сдача норматива. Для симптомов не обходить остановку нагрузки.

## Что записывать после каждой недели

- Отображённая дата и названия назначений.
- Количество лёгких и интенсивных тренировок.
- Общий назначенный километраж (с учётом разминки, отрезков и заминки).
- Понятность инструкций: темп, скорость дорожки, метры/минуты, отдых.
- Что произошло после пропусков, неполной тренировки и жалобы на боль.
- Ошибки / сообщения, которые непонятны без разработчика.

**Критерий испытания:** технически можно пройти цикл и восстановить
его после перезагрузки; содержание тренировки понятно; опасные нарушения
нагрузки отсутствуют; тестовая информация не влияет на рабочую версию.
Симуляция не подтверждает, что человек физически достигнет цели.
