# QA issue #23 — автономный прогон полного цикла подготовки (8–12 недель) в реальном браузере

Ничего здесь не меняет методику, health-проверки и STOP: найденные проблемы **записываются** (`reports/qa-issue-23/defect-log.md`), а не исправляются. Данные вымышленные.

## Запуск

```bash
# Node >= 22.18, один раз: npx playwright install --with-deps chrome
npm ci
npm run qa:issue23:ci        # сборка тестового билда + все сценарии + отчёт (код выхода = код Playwright)
# по частям:
npm run qa:issue23           # только Playwright (поднимает `build:testing` и vite preview на :4176 сам)
npm run qa:report            # собрать report.md / defect-log.md / CSV из уже сохранённых результатов
npx playwright test -c playwright.qa.config.ts -g "p3-"     # один профиль
QA_DEFECT_RAW=1 npx playwright test -c playwright.qa.config.ts defects.spec.ts   # повторы дефектов как обычные тесты (покажут реальный отказ)
QA_VERBOSE=1 ...             # построчный прогресс по виртуальным дням
```

Переменные: `QA_OUT_DIR` (JSON/CSV), `QA_SHOT_DIR` (скриншоты), `QA_PLAYWRIGHT_JSON` (сырой JSON-репортёр). По умолчанию всё пишется в `reports/qa-issue-23/{data,screenshots,raw}`.

Работает **только** с локальной тестовой сборкой (`VITE_TEST_MODE=1`); боевой сайт и реальный localStorage не затрагиваются (каждый тест — чистый контекст браузера). Виртуальная дата — панель «Тестовый календарь».

## Что где

| Файл | Назначение |
|---|---|
| `profiles.ts` | детерминированные фикстуры 5 профилей, описание ограничений/реалистичности/дней |
| `model.ts` | модель поведения (seed, mulberry32): ON_PLAN / PARTIAL / SYMPTOMS / TOO_HARD, допустимые вердикты движка |
| `cycle.ts` | «режиссёр»: день за днём, директивы сценария (перенос, неполная, пропуск 3–4 дней, здоровье, смена даты, замер, итог) |
| `driver.ts` | действия через UI, скриншоты, проверки на каждом шаге, перезагрузки |
| `invariants.ts` | независимые от движка инварианты по сохранённому состоянию |
| `analysis.ts` | таблица недель (разминка/основная/заминка, EASY/quality, резерв), проверки правдоподобия |
| `full-cycle.spec.ts` | по тесту на профиль: полный цикл |
| `cross-cutting.spec.ts` | двойные клики, +7 дней с незакрытой, перезагрузки/назад-вперёд, повреждённое хранилище, ранний итог |
| `defects.spec.ts` | короткие повторы найденных дефектов (`test.fail` → «ожидаемый отказ») |
| `known-defects.ts`, `defect-catalog.ts` | сопоставление проверок и дефектов, описание дефектов |
| `report.ts` | агрегатор: `report.md`, `defect-log.md`, `summary.json`, `all-profiles.csv`, `weekly-load.csv`, `checks.csv` |

## Seeds (фиксированные, одно значение на профиль)

| Профиль | Seed | Недель до старта |
|---|---|---|
| p1-novice-no3k (не бегает 3 км) | 20261012 | 12 |
| p2-18min-5-10km | 20261013 | 10 |
| p3-15-30-12-18km | 20261014 | 8 |
| p4-14-30-25-30km | 20261015 | 10 |
| p5-strong-high-base | 20261016 | 12 |

Старт всех циклов — понедельник 2026-10-12. Seed управляет только выбором значений внутри допустимых диапазонов плана (RPE, темп отрезков); последовательность событий (директивы) задана детерминированно в `cycle.ts › directivesFor`. Повторный запуск с теми же seed даёт тот же журнал.

## Модель поведения (кратко)

| Режим | Что вводит пользователь | Ожидаемый вердикт движка |
|---|---|---|
| ON_PLAN | 100 %, RPE и темп внутри диапазонов плана, симптомов нет | GREEN / GREEN_PLUS |
| PARTIAL | «примерно половина» | YELLOW |
| TOO_HARD | 100 %, RPE на 2 выше верхней границы плана, необычная усталость | YELLOW |
| SYMPTOMS | боль 4 + изменилась техника | RED → STOP/пауза |

Тест падает, если вердикт движка не входит в допустимое для режима множество (безусловного «GREEN» нет). Блокировки (STOP, перенос просроченной, ввод не по порядку, обновление плана при незакрытой тренировке, повторная проверка без подтверждения, дата экзамена в прошлом, ранний итог) проверяются как **ожидаемые**.

## Как читать результат проверки

`PASS` — выполнено; `FAIL` — непроанализированный отказ (валит тест); `KNOWN_FAIL` — отказ, связанный с записью в `defect-log.md` (не скрыт, считается отдельно).
