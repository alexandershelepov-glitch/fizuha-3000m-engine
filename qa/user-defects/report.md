# Приёмка методики №4: три дефекта iPhone — причины, исправления, проверка

Дата: 2026-11-01. Ветка: `feature/methodology-v4-eight-week` (PR №52). Production (`main`) не изменялся.

## Установленные причины

### Дефект №1 — старый план вместо методики №4

Причина воспроизведена на реальном сценарии анкеты, а не предположена:

1. `defaultDraft()` предлагал норматив через **56** дней после старта (дата устройства).
2. `eligibleForV4()` принимала срок **53–56** дней.
3. `createEngine()` включал методику только при сроке **≤ 55** дней.
4. Итог: пользователь принимал предложенные даты, приложение строило **старый** план —
   9 календарных недель (01.11–27.12.2026), спокойный бег, вводные интервалы
   `INTRO_QUALITY`, промежуточные контроли `CONTROL`.

Проверка до исправления (`createEngine`, старт 01.11.2026, норматив 27.12.2026,
результат 14:30, 3×/нед, 20 недель, 16 км, длительная 6 км):

```
eligibleForV4: true   isV4Candidate: true   methodology: null
queue: INTRO_QUALITY, EASY, LONG_EASY
```

Тот же профиль со сроком 53/54/55 дней включал методику и давал 24 назначения.
Отсюда же девятая календарная неделя: без включённой методики календарь строится
по календарным понедельникам, а не по неделям цикла.

Дополнительно: экран «Проверьте данные» не сообщал, какая методика будет создана,
поэтому подмена происходила молча. Сохранённое состояние iPhone недоступно извне,
но любой цикл с промежутком 56 дней детерминированно получал старый план — это и
наблюдалось.

### Дефект №2 — неудобный просмотр календаря

Нажатие только выделяло день; параметры показывались в отдельной панели ниже
доски, а для прогнозных занятий полноценной карточки не было вовсе.

### Дефект №3 — ввод времени отрезков

Поле `repeat.seconds` имело `inputMode="numeric"` и ожидало `М:СС`. На iOS
цифровая клавиатура не содержит двоеточия, поэтому `1:56` ввести было нельзя.

### Оставлены намеренно (нужно отдельное решение)

Ветки-предпросмотры внутри единственного проекта. Публичный API и CLI Layero не
предоставляют удаление отдельного окружения (окружение живёт вместе с веткой), а
удалять GitHub-ветки запрещено условиями задачи. Их PR всё ещё открыты, поэтому
это ещё и история отката:

- `fix/methodology-v4-future-cycle-start` (дубль-ветка той же работы),
- `feature/staging-pwa-deploy` (PR №41),

- `testing/virtual-clock` (PR №22).

Рекомендация: удалить их в панели Layero после закрытия соответствующих PR либо

временные окружения только на время конкретной проверки.
