# Проверка даты начала цикла

Анкета сохраняет выбранную дату начала отдельно от даты устройства. Движок получает обе даты; до старта очередь не содержит тренировок до выбранной даты. Дату начала и дату норматива можно выбрать в анкете, при этом для подходящего профиля контроль должен приходиться на последние три дня восьмой недели (53–55 дней после старта). Календарь методики показывает восемь последовательных недель от начала, независимо от дня недели. Старые сохранения остаются читаемыми.

Если методика №4 не применима, календарь сообщает об этом и перечисляет условия её применения; существующая защитная логика продолжает действовать. Перенос тренировки на дату до начала запрещён. Дату норматива также нельзя изменить на дату до начала цикла.

Проверка: обычный путь анкеты при дате устройства 01.11.2026, старте 02.11 и нормативе 26.12; 24 карточки, дозировки, темпы, паузы, разминка и заминка, отсутствие записи результата до дня тренировки, отсутствие изменений хранилища при просмотре, повторная загрузка. Второй браузерный сценарий начинает цикл во вторник, третий проверяет объяснение для недостаточной беговой базы. Отдельные тесты проходят реальное сохранение и восстановление, старт за пределами ближайших семи дней, другие месяцы, первый день и переход ко второй неделе, а также оба режима прогноза. Сценарии часов устройства используют браузерные часы, без QA-режима или специальной ветки виртуального времени.

Команды: `npm test`, `npm run test:ui`, `npm run typecheck`, `npm run lint`, `npm run test:e2e`, `npm run test:e2e -- e2e/future-start.spec.ts`. Полный браузерный набор: 51 пройден, 2 QA-only сценария пропущены в обычной сборке. Расширенная проверка даты: три браузерных сценария. Проверка реального HTTPS и идентичности версии выполняется отдельно после отправки.
